# Find a Tender —Internal Procurement Search Tool

A tool for searching UK government procurement notices from [Find a Tender](https://www.find-tender.service.gov.uk), filtered to surface opportunities relevant to carbon and biodiversity markets.

---

## What this does

The Find a Tender website lists all UK public procurement notices. This tool automatically fetches those notices, filters them by relevance to your work (biodiversity net gain, carbon credits, nutrient mitigation, etc.), and presents the results in a clean, searchable format with a downloadable CSV and an interactive map.

## How it works (phase 1)

The core script (`scripts/fetch_tenders.py`) does the following:

1. Calls the [Find a Tender OCDS Release Package API](https://www.find-tender.service.gov.uk/Developer/Documentation) — no API key required, it is fully open
2. Fetches results in pages of up to 100 notices using cursor-based pagination
3. Filters results locally using whole-word keyword matching across title and description fields
4. Prints matched results to the terminal with key fields: title, buyer, postcode, value, closing date, and which keywords matched

- Python 3.12 (via Miniconda — see below)
- Git
- A Miniconda environment named `find-a-tender`

```bash
# Clone the repository
git clone https://github.com/ChloeCreak/find-a-tender.git
cd find-a-tender

# Create and activate the conda environment
conda create -n find-a-tender python=3.12
conda activate find-a-tender

# Install dependencies
pip install -r requirements.txt
```

### Running the script

```bash
conda activate find-a-tender
python3 scripts/fetch_tenders.py
```

## Configuration

At the top of `scripts/fetch_tenders.py`, two constants control behaviour:

| Constant | Default | Description |
|----------|---------|-------------|
| `TEST_KEYWORDS` | See below | List of keywords to filter by |
| `MAX_PAGES` | `5` | How many pages to fetch per run (each page = up to 100 tenders) |
| `PAGE_SIZE` | `100` | Results per API request (max 100) |

### Default keywords

```python
TEST_KEYWORDS = [
    "Biodiversity Net Gain",
    "BNG",
    "biodiversity",
    "carbon",
    "carbon credits",
    "carbon neutral",
    "nutrient mitigation",
    "phosphate mitigation",
    "nitrate mitigation",
]
```

Keywords are matched as whole words and phrases, case-insensitively. `"carbon"` will not match `"carbonate"`. `"BNG"` will not match `"bingo"`.

## Filtering — current approach and future improvements

Future improvements generated by Claude.

### Current: keyword matching

The script currently uses **whole-word regex matching** across tender titles and descriptions. A tender is included if it matches any keyword in the list.

This is functional but has limitations — it only finds tenders that use your exact terminology, and misses synonyms or related concepts.

### Planned improvement 1: CPV code filtering

Every tender carries a **CPV (Common Procurement Vocabulary) code** — a standardised EU classification. Rather than searching free text, filtering by CPV code is more precise and structured. For example:

- `90700000` — Environmental services
- `77000000` — Agricultural, forestry, horticultural, and related services
- `90711000` — Environmental impact assessment

A curated list of relevant CPV codes could serve as the primary filter, with keywords as a secondary layer.

### Planned improvement 2: Fuzzy matching

Handles typos, hyphenation variants, and slight phrasing differences. For example, `"bio-diversity"` or `"biodiversty"` would still match. The `rapidfuzz` library makes this straightforward to add.

### Planned improvement 3: TF-IDF scoring

Rather than a binary match/no-match, **TF-IDF (Term Frequency–Inverse Document Frequency)** ranks results by relevance. A tender where your keywords appear frequently and prominently scores higher than one where they appear once in passing. The `scikit-learn` library has this built in.

### Planned improvement 4: Semantic similarity

The most powerful near-term upgrade. Instead of matching exact words, semantic similarity understands **meaning**. A tender about `"habitat creation"` or `"ecological offsetting"` would surface as relevant even without containing the word `"biodiversity"`.

This uses sentence embedding models from the `sentence-transformers` library. Each tender description is converted to a vector, and results are ranked by cosine similarity to a target description of your domain. More complex to set up but genuinely valuable for a niche domain like environmental land management.

### Planned improvement 5: ML classification (long term)

The most sophisticated option. You would manually label a set of tenders as relevant or not relevant, train a binary classifier on those labels, and apply it to new tenders automatically. The model improves as more labelled examples are added. Requires a few hundred labelled examples to be reliable — a later-stage option once the tool is in regular use.

## API notes

- **Authentication**: None required. The Find a Tender API is fully open.
- **Pagination**: Cursor-based. The API returns a `next` URL in the `links` field of each response. The script follows this automatically.
- **Rate limiting**: HTTP 429 responses include a `Retry-After` header. The script handles this gracefully and displays a clear message.
- **Timeout**: All requests time out after 30 seconds. The API can be slow — this is normal.
- **Data format**: [OCDS (Open Contracting Data Standard)](https://standard.open-contracting.org/) version 1.1.5

## Troubleshooting

### "The request timed out"
The Find a Tender API is sometimes slow. Wait a moment and run the script again. If it persists, check [https://www.find-tender.service.gov.uk](https://www.find-tender.service.gov.uk) is accessible in your browser.

### "No module named requests"
Your conda environment may not be active. Run `conda activate find-a-tender` and try again.

### "No matches found"
Either no tenders matching your keywords were published recently, or `MAX_PAGES` needs increasing to search further back. Try raising `MAX_PAGES` to `20` in the script.

### The script runs but shows nothing
Make sure you saved the file in VS Code before running it (`Cmd+S`).
